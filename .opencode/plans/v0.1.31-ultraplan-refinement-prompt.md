## Required Refinements (apply to every phase)

For each of Phases 0–5:

1. **Pre-flight checks** — What must be true before the phase starts? (e.g., "Apple Developer portal access verified", "no open PRs against main", "1Password vault ready").

2. **Atomic task breakdown** — Split each numbered step into individual tasks. Each task gets:
   - Task ID (e.g., `0.3.1`)
   - Title (imperative verb, ≤80 chars)
   - Depends-on (other task IDs or "none")
   - Files touched (repo-relative paths with line numbers when applicable)
   - Acceptance criteria (testable command or observable state — NOT "done when feels done")
   - Estimated time (15min / 1hr / 4hr / 1day buckets)
   - Confidence rating (0.0–1.0) that the task succeeds first try

3. **Rollback procedure** — If the phase fails midway, how do you back out without leaving the repo broken? Critical for: `git filter-repo` (Phase 0), Rust module deletions (Phase 2), `tauri ios init` (Phase 1).

4. **Hidden dependencies discovered** — Things the canonical plan doesn't mention that you find by reading the actual code. Cite file:line evidence. Example: "Phase 2 deletes `event_bridge.rs` but `lib.rs:147` references `EventBridge::new()` outside the `tauri::generate_handler!` block — must also remove that line."

5. **Per-phase self-evaluation** — Confidence rating 0.0–1.0 and the top 3 uncertainties.
